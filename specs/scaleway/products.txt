# Produits Scaleway suivis par le générateur, un par ligne.
#
#   <slug-portail> [<nom-produit>] <version>
#
# Le slug est celui de l'URL du portail developers, et il ne coïncide pas
# toujours avec le nom du produit dans les SDK. Mesuré sur le portail :
# baremetal s'y appelle elastic-metal, k8s s'y appelle kubernetes, lb s'y
# appelle load-balancer/zoned. Un produit ajouté ici se vérifie sur sa page,
# il ne se devine pas depuis le SDK.
#
# Instance a servi de premier produit : la chaîne complète a fonctionné sur lui
# avant qu'un second n'arrive. `lb` est ce second, et il est choisi pour une
# raison mesurable plutôt que par appétence : la stack d'exemple déploie déjà un
# load balancer, donc ses modules sont exercés contre le cloud réel dès le
# premier jour, sans écrire de nouvelle plateforme. C'est le produit dont la
# preuve coûte le moins cher.

instance v1
load-balancer/zoned lb v1

# Le troisième produit, et il n'entre pas sur son nombre de routes. La
# collection officielle livre `k8s_cluster` et `k8s_pool`, tous deux en
# `state: present/absent` : elle crée des clusters et n'offre rien pour les
# exploiter ensuite. C'est la place que #240 décrit, derrière elle et non en
# face. `kubernetes` sur le portail, `k8s` dans les SDK.
kubernetes k8s v1

# Le lot réseau, promu du suivi à la génération (#258). Les deux étaient
# versionnés sous `suivis/` parce que l'inventaire dynamique les interroge à
# chaque exécution : `ipam.list_i_ps_all`, `vpc.list_private_networks_all` et
# `vpc.list_vp_cs_all` portent la jointure qui donne son adresse privée à
# chaque machine, et cette jointure lit ses champs par `getattr(..., None)`,
# donc un champ renommé en amont rend `None` en silence et l'inventaire un parc
# muet.
#
# **Ce qui a changé n'est pas le besoin de les suivre, c'est ce qu'on en fait.**
# La collection n'offrait aucun module pour deux APIs qu'elle appelle à chaque
# inventaire : lire une adresse réservée ou le DHCP d'un réseau privé
# demandait d'écrire du `uri:` à la main. L'argument qui les tenait hors
# génération - « élargir à un produit que la collection ne sert pas ajouterait
# des UNKNOWN permanents » - ne tient plus : elle les sert, et les deux sortent
# à zéro UNKNOWN.
ipam v1
vpc v2

# Suivis sans être générés. `suivi` en fin de ligne range le contrat sous
# `suivis/`, où le générateur ne le voit pas : il n'y a ni module, ni rapport,
# ni golden pour ces produits. Ils restent versionnés pour la raison qui y a
# mis ipam et vpc : l'inventaire lit leurs champs, et une dérive d'amont s'y
# verrait sinon comme un parc muet.
elastic-metal baremetal v1 suivi
apple-silicon applesilicon v1alpha1 suivi
